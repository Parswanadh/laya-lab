## 0. Verdicts

| prediction (from `findings/P1-mechanism.md`) | verdict | decisive evidence |
|---|---|---|
| **P-a** widening the sliding window (128→256/512/1024) recovers part of the loss | **REFUTED** | No dose–response; the +1 item at pad=7000 on the P1 item set (n=20, p=1.0) **reverses to −19 items (p=0.0094)** on the label-balanced n=120 set; and the *narrowing* ablation (64) moves pad=7000 by the same +1 item. Widening at 1024 additionally **collapses** pad=4000: 0.600 → 0.150 (p=0.012) |
| **P-b** all layers global recovers more, at quadratic cost | **REFUTED** (both halves) | Accuracy *falls* at every length ≥ 1000 — 0.000 at pad=1000, and 0.333 at pad=7000 (n=120) **exactly the majority-class rate, p=7.5e-9**, with all 120 items predicted `technical`. Cost: **+0–6%** median latency, not a multiple |

Both verdicts are about *these two knobs as stated*. Neither result bears on P-c (a cross-attention
head), which is a different mechanism and is not tested here.

## 1. What was patched, and the proof that it was live

### 1.1 The mechanism, re-verified against the installed library (not quoted from the issue)

`transformers/models/modernbert/modeling_modernbert.py` (4.57.6):

- **line 465** at construction: `if layer_id % config.global_attn_every_n_layers != 0:
  self.local_attention = (config.local_attention // 2, config.local_attention // 2)` else `(-1, -1)`.
- **line 412** in `sdpa_attention_forward`: `if local_attention != (-1, -1): attention_mask =
  sliding_window_mask` — the **per-layer init-time tuple** decides the branch.
- **line 938** in `ModernBertModel._update_attention_mask`: the sliding mask is rebuilt every
  forward from `self.config.local_attention // 2`.

Two corrections to the issue text, both checked at runtime (`config_before` in every summary):

- `lyr.attention_type` **does not exist** in 4.57.6 (`has_attention_type_attr=false`) and neither
  does `lyr.self_attn` (`has_self_attn_attr=false`); the attribute the SDPA path reads is
  **`lyr.attn.local_attention`**. Patching `attention_type` would have been an inert no-op.
- `config.global_attn_every_n_layers` alone is inert after construction, as the issue warned; the
  `attention_type`/`self_attn` part of the suggested fix is inert too.

Arms applied exactly as: **P-a** = `config.local_attention = W` **and** every sliding layer
`attn.local_attention = (W//2, W//2)`; **P-b** = `config.global_attn_every_n_layers = 1` **and**
every layer `attn.local_attention = (-1, -1)`.

**RoPE is not a confound here (measured).** `all_layers_same_rope_inv_freq = true` in every
summary, from comparing every layer's `rotary_emb.inv_freq`: mmBERT uses theta 160000 for global
*and* sliding layers, so converting a sliding layer to global changes **the mask only**, not its
positional encoding. This corroborates R-001 §3.3 from our own model rather than from the paper.

### 1.2 Liveness: the mask each layer actually handed to SDPA

`MODERNBERT_ATTENTION_FUNCTION["sdpa"]` is wrapped for the first forward of every cell; for each of
the 22 encoder layers it records the mask tensor actually passed to
`F.scaled_dot_product_attention` and decodes the **max attended distance of the last query row**.
An arm whose observed mask disagrees with its spec raises and is not scored — no silent no-op can
be reported as "no effect". Observed histograms (`liveness.json`, one row per pad):

| arm | spec (sliding layers / half-window) | observed last-row max attended distance | verdict |
|---|---|---|---|
| baseline, pad=7000 (L=7076) | 14 sliding ±64, 8 global | `{64: 14, 7068: 8}` | live |
| w64, pad=0 (L=76) | 14 sliding ±32 | `{32: 14, 68: 8}` | live |
| w256, pad=7000 | 14 sliding ±128 | `{128: 14, 7068: 8}` | live |
| w512, pad=7000 | 14 sliding ±256 | `{256: 14, 7068: 8}` | live |
| w1024, pad=4000 (L=4076) | 14 sliding ±512 | `{512: 14, 4068: 8}` | live |
| allglobal, pad=7000 | 22 global | `{7068: 22}` | live |

**And the shipped path does apply its window** — the baseline is `{64: 14, …}`, not `{L-1: 22}`.
That closes, for our stack, the hazard R-001 §2.4 handed to `engineer` (a production path that
silently attended globally). Every one of the 41 scored cells passed this assertion.

| control | result | what it rules out |
|---|---|---|

## 3. Results — label-balanced item set (`balanced-v1`, n = 120, 40 per label)

The P1 caveat "the 0.450 floor is the majority class, so *collapsed to prior* is supported but not
proven" is answered here: this set is label-balanced, so majority-class = **0.333** and a constant
answer cannot exceed it. Same construction, same protocol; `n = 120` per cell (M-001's power table
gives 80% power at n≈77 for a 0.10 effect at 0.10 discordance).

| arm | pad=0 | pad=7000 | Δ at 7000 [95% CI] | b / c | McNemar p | median lat. 7000 |
|---|---|---|---|---|---|---|
| **baseline** | 0.800 (96/120) | **0.567 (68/120)** | — | — | — | 1.960 s |
| w512 (P-a) | 0.800 (96/120) | **0.408 (49/120)** | **−0.158 [−0.267, −0.050]** | 34 / 15 | **0.0094** | 1.898 s |
| allglobal (P-b) | 0.800 (96/120) | **0.333 (40/120)** | **−0.233 [−0.308, −0.158]** | 28 / 0 | **7.5e-09** | 1.910 s |

The P-a hint from the n=20 set does not replicate: at n=120 the widened window is **significantly
worse** than the shipped config. And at n=120 the all-global arm predicts **`technical` for all 120
items** with mean max-prob 0.258 → accuracy 40/120 = exactly the majority rate. "Stopped reading the
document and fell back on a constant answer" is now a *measured* statement for that arm, not an
inference from an imbalanced set.

At pad=0 all three arms score 0.800 (96/120) and w512 ≡ allglobal bit-identically; baseline differs
only numerically (`max|Δp_gold| = 0.034`, 120/120 identical predictions) because its ±64 window
masks the few pairs beyond distance 64 in an 83-token sequence.

## 4. Mandatory controls

**4.1 Ablation control — narrower window (`local_attention = 64`).** It does **not** behave as the
mechanism predicts. At pad=7000 it *matches the widening arms item-for-item* (0.500 = baseline + 1
item), and it is the only arm that loses the short-context case: pad=0 0.850 vs 0.950 (2 items,
McNemar p=0.5, not significant at n=20 — but mechanically explained: at pad=0 the sequence is 76
tokens and the option markers sit in the first 45, so a ±32 window cannot reach the request tail;
the mask-binding control above shows the same arm at `max|Δp_gold| = 0.578` versus baseline).
**Narrowing and widening both "help" at pad=7000 and neither is dose-dependent, so the +1 item at
pad=7000 is not attributable to long-range mixing.**

**4.2 Short-context regression (pad=0).** Every widening arm and all-global hold pad=0 exactly
(0.950 on the P1 set, 0.800 on the balanced set; bit-identical where the mask does not bind). The
only pad=0 loss is the narrowing ablation. So P-a/P-b do not break short context — they fail the
long-context case instead, and P-a additionally breaks the **mid**-length cases the baseline handles
(pad=1000: 0.900 → 0.650 at w512; pad=4000: 0.600 → 0.150 at w1024). A pad=7000 gain that costs the
pad=1000 case is not shippable either; here there is no gain to weigh against it.

**4.3 Construction control (secondary, and it matters for the program).** Upstream's own rule
(`FILLER * round(pad/per_rep)` **plus** the `"\n\nActual request: "` delimiter, `bench_long_context.py`)
scores much higher than P1's exact-token rule with no delimiter, at the same nominal pad:

| construction | pad=0 | pad=4000 | pad=7000 |
|---|---|---|---|
| `p1_exact` (P1's `place()`) | 0.950 | 0.600 | 0.450 |
| `upstream_rule` (upstream's bench) | 0.950 | **0.850** | 0.500 |

The two also differ in realised length (4018 vs 3929 tokens at pad=4000). **This is a construction
sensitivity of the same order as the effects being chased**: upstream's published 0.85–0.90 at
`limit=8192` and P1's 0.60/0.45 are not measuring the same document. All arm comparisons in this
finding are within one construction (`p1_exact`), so the verdicts are unaffected — but any claim
that "the model degrades at 8192" should say which document rule it used.

**4.4 Truncation.** `input_tokens_max` = 76 (pad=0) … 7083 (pad=7000) across 41 cells, all below
`limit=8192`; zero items flagged truncated. Nothing here is a budget effect.

## 5. Cost — reported honestly (and it is *not* quadratic)

Medians over 19 timed items per cell at pad=7000 (first item of each cell excluded as warm-up),
plus an interleaved measurement (`cost_interleave.json`) that removes drift.

| arm | median (sweep, P1 set) | median (sweep, balanced n=120) | interleaved median | ratio vs baseline | peak VRAM (reserved) |
|---|---|---|---|---|---|
| baseline | 1.845 | 1.960 | see `cost_interleave.json` | 1.00 | 2068 MiB |
| w64 | 1.762 | – | – | 0.96 | 2068 MiB |
| w128 | 1.843 | – | – | 1.00 | 2068 MiB |
| w256 | 1.923 | – | – | 1.04 | 2068 MiB |
| w512 | 1.944 | 1.898 | – | 1.05 / 0.97 | 2068 MiB |
| w1024 | 1.924 | – | – | 1.04 | 2068 MiB |
| **allglobal** | **1.959** | **1.910** | – | **1.06 / 0.97** | 2068 MiB |

**Noise floor:** `allglobal` and `allglobal_w512_combo` are *bit-identical computations* yet their
medians differ by 4.6% (1.959 vs 1.873 s) in the same process. Differences below ~5% are therefore
not resolvable here; the honest statement is that **going from 8 global layers to 22 costs at most a
few percent, not a multiple**, and that window width has no measurable cost.

**Why there is no quadratic blow-up (measured + mechanism).** In this execution path the window is a
*dense bias*, not a sparse kernel: `ModernBertModel._update_attention_mask` builds a full
`[1,1,L,L]` float32 `sliding_window_mask` and the same-shaped `global_attention_mask`, and
`sdpa_attention_forward` passes one of them as `attn_mask` to `F.scaled_dot_product_attention` on
every layer. `mask_evidence.json` records the mask shape/dtype every layer received for four arms,
and `sdpa_microbench.json` times the two masks against no mask at the same L. Consequence: **the
14 "local" layers were already paying dense-attention cost while being restricted to ±64** — the
window bought representation, not speed, and removing it cannot cost what a windowed kernel would
have saved. (At pad=7000, L=7076, one such mask is 191 MiB in fp32 and two are built per forward,
which is what dominates the 2068 MiB peak.)

## 6. What this says about the P1 mechanism, and what it does not

- P1 predicted that the shortage of long-range paths (8 of 22 layers) plus dilution explains the
  long-document loss, and that the two cheapest ways to add paths would recover part of it.
  **Adding paths does not recover accuracy — it destroys it** (all-global: 0.000 at pad=1000,
  exactly-majority at pad=7000, n=120, p<1e-9), and widening is either inert or harmful.
- The strongest single observation against the "the markers need a privileged path" reading is that
  the *narrower* window produces the same pad=7000 number as the wider ones: the arms are not
  ordered by how much long-range mixing they permit.
- The pattern across arms is instead consistent with the model's **trained locality being
  load-bearing**: every intervention that changes the attention pattern away from the trained one
  produces a length-dependent *constant* output, i.e. a representation collapse, rather than a
  graded accuracy change. This is an observation, not a test of P-c, and it does not show that
  dilution is or is not the operative mechanism.
- **Not tested here:** P-c (a cross-attention head), any trained adaptation, retrieval/routing, or
  any length beyond 8192.

## 7. Caveats

- `n = 20` on the P1 item set: one item = 0.05, a cell is ±0.22 at 95%. The n=20 rows are for
  comparability with P1 probe B/C, **not** for resolving small effects — the n=120 balanced set is
  where the verdicts are decided, and the two sets disagree in sign for w512.
- Single repeated filler paragraph (both constructions), synthetic needle-at-end task. The needle is
  at fraction 1.0 in every cell here; probe B's position sweep is not re-run.
- fp32, matching P1. The shipped default is bf16 autocast; probe A showed no accuracy difference
  between dtypes at pad=4000, so the dtype is not expected to matter, but the *latency* ratios above
  are fp32 ratios.
- Peak VRAM is `reserved` and includes the allocator's cached pool from earlier, longer cells in the
  same process; per-cell pad=0 numbers are inflated by that cache. The arm-level maximum (2068 MiB)
  and the pad=7000 cells are comparable across arms.
- `other` never appears as a gold label on the P1 set, so any arm drifting to `other` scores 0 there
  (that is a property of the item set, and it is why the balanced set was added).
- Latency differences below ~5% are inside the measured noise (see §5).
